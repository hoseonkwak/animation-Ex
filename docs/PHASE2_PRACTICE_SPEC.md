# Phase 2 · Practice 상세 설계

문서 상태: 설계 기준 v0.1
범위: 로그인 없는 자유 연습, 자체 시작 코드, 격리 실행, 브라우저 저장과 CodePen 내보내기
기준 문서: `RENEWAL_PRODUCT_SPEC.md`, `DECISIONS.md`, `UX_SPEC.md`, `CONTENT_SCHEMA.md`, `QUALITY_GATES.md`

## 1. 목표와 출시 경계

사용자는 탐색한 애니메이션에서 `연습하기`를 눌러 별도 URL의 작업 공간으로 이동하고, HTML·CSS·JavaScript를 수정하면서 **자신의 코드가 실제로 실행되는 화면**을 본다. 원본 CodePen 화면은 비교할 수 있는 참고 자료이며, 녹화나 이미지가 실행 화면을 대신하지 않는다.

- Phase 2: 자유 연습, 자체 제작 시작 코드가 있는 Practice Kit, 자동·수동 실행, 콘솔, 복구, 로컬 저장, CodePen 내보내기.
- Phase 3: 단계별 미션, 힌트, 자동 판정, 해설과 튜토리얼. Phase 2에서 빈 Mission 탭이나 작동하지 않는 학습 버튼을 표시하지 않는다.
- 로그인, 서버의 사용자 코드 저장, 원본 Pen 코드 자동 추출, 일반 웹 코드 자동 생성은 Phase 2에 넣지 않는다.
- 자유 연습은 무료이며 관리자 한 명·Light 기본 테마 원칙을 유지한다.

## 2. 진입과 콘텐츠 권리

| 출발점 | 시작 상태 | 사용자에게 보이는 설명 |
| --- | --- | --- |
| 자체 제작·검증된 Practice Kit이 있는 예제 | 해당 Kit의 HTML·CSS·JS 시작 코드 | `시작 코드로 연습하기` |
| Kit이 없는 원본 CodePen 예제 | 서비스가 새로 만든 빈 기본 코드. 원본의 코드·텍스트·에셋은 복사하지 않음 | `빈 코드로 연습하기 · 원본을 참고하며 직접 만들어요` |
| Practice 홈의 `새 연습` | 출처 없는 빈 기본 코드 | `새 연습 시작` |
| 최근 연습 | 같은 브라우저의 마지막 초안 | `이어서 연습` |

원본 Pen은 제작자, 제목, 링크와 라이선스를 참고 패널에 계속 표시한다. 필요할 때 버튼을 눌러 **원본 CodePen의 실제 Embed**를 로드한다. 원본을 보면서 사용자가 직접 작성한 코드는 사용자 초안이며, 원본의 내부 코드를 가져와 편집기에 미리 채우지 않는다. Kit을 붙일 때에는 코드 사용 권리를 확인하고 출처·라이선스·독립 제작 여부를 기록하며 `QUALITY_GATES.md`의 Practice Gate를 통과시킨다. 빈 코드 연습은 해당 예제의 `practice-ready` 상태를 뜻하지 않는다.

## 3. 경로와 사용자 흐름

| 경로 | 역할 |
| --- | --- |
| `/practice` | 새 연습 시작, 최근 초안, Practice Kit이 준비된 예제 |
| `/practice/new?reference=:slug` | 브라우저에 새 초안을 만든 뒤 `/practice/drafts/:id`로 주소를 교체. `reference`는 선택 사항 |
| `/practice/drafts/:id` | 사용자가 직접 만든 초안의 작업 공간 |
| `/practice/examples/:slug` | 검증된 Practice Kit에서 시작하거나 해당 예제의 기존 초안을 이어갈지 선택한 뒤 초안 주소로 이동 |

예제 상세의 `연습하기`는 같은 탭의 독립된 Practice 페이지로 이동한다. 저장한 예제의 `나중에 연습`도 같은 진입 규칙을 사용한다. Kit 선택 후에도 새 초안 ID를 만들고 `/practice/drafts/:id`로 이동한다. URL에 코드나 개인정보를 넣지 않는다. `reference`는 실제 공개 Entry의 slug로만 해석하며, 없는 초안 주소는 오류를 숨기지 않고 `새 연습 시작`과 원래 예제로 돌아가는 링크를 보여준다.

```text
예제 상세 → 연습하기 → 시작 코드 확인/초안 복원 → 편집 → 저장 → 격리 실행
                                                    ├→ 원본 실행 화면 참고
                                                    ├→ 마지막 정상 코드 복구
                                                    └→ CodePen으로 내보내기
```

## 4. 화면 구조

### 데스크톱 (1024px 이상)

```text
┌ 제목 · 원본/초안 상태 ─ 자동 실행 ─ Run ─ 초기화 ─ CodePen ─ 나가기 ┐
│ HTML │ CSS │ JS     편집기       ║       내 실행 화면          │
│                         드래그로 폭 조절                      │
├ Console · 오류 · 실행 시각 ─────────── 원본 참고 열기 ────────┤
└ 저장 상태 · 브라우저 저장 안내 ────────────────────────────────┘
```

- 편집기와 Preview는 기본 1:1이며 35:65~65:35 범위에서 조절한다. 폭은 현재 브라우저에 저장한다.
- 작업 화면은 탐색 페이지의 큰 Hero를 반복하지 않고 화면 너비를 작업에 사용한다. 제목·출처·저장 상태는 한 줄에 정리하고 편집기·Preview의 경계를 명확히 한다. 공개 사이트의 Liquid 색상 토큰을 쓰되 코드 읽기 영역에는 장식 효과를 두지 않는다.
- 상단에는 작업 중인 예제 이름과 `저장됨/저장 중/저장 실패`, `자동 실행` 스위치, `Run`, `초기화`, `CodePen으로 보내기`, `나가기`를 둔다. Preview 헤더에서 전체 화면을 연다.
- HTML·CSS·JS 편집 탭은 각 파일의 수정 여부를 표시한다. 실행 결과는 Preview에만 보이며 편집 화면에서 애니메이션을 배경으로 실행하지 않는다.
- Console은 Preview 아래 접을 수 있는 패널로 두고 오류가 생기면 펼쳐 요약·파일·줄을 먼저 보여준다. 사용자 로그는 양과 길이를 제한한다.
- `원본 참고`는 보조 패널을 연다. 출처 정보와 원본 Pen 링크는 즉시 보이고 원본 Embed는 사용자가 `실행 화면 보기`를 눌렀을 때만 시작한다. 닫으면 iframe을 제거한다.
- 빈 기본 코드는 의미 없는 데모 애니메이션 대신 최소 HTML 요소 하나, 기본 CSS와 비어 있는 JavaScript로 시작한다. 참고 예제의 라이브러리가 허용 목록에 있으면 사용자가 추가할 수 있게 제안한다.

### 태블릿·모바일

- 1023px 이하에서는 조절 손잡이를 없애고 Code/Preview 탭으로 전환한다. Console은 별도 패널, 원본 참고는 전체 화면 dialog로 연다.
- Preview 탭의 `Run`, 오류 요약과 전체 화면을 항상 접근 가능하게 둔다. 키보드가 열려 있을 때 코드 입력 영역 높이가 사라지지 않게 한다.
- 639px 이하에서는 주요 행동을 `Run`과 `저장 상태` 중심으로 배치하고 초기화·내보내기·자동 실행은 명시적인 더보기 메뉴에 둔다. 터치 대상은 최소 44×44px이다.
- Theme은 공개 사이트 설정을 따르고, 편집기와 Console의 명도 대비를 Light·Dark에서 각각 확인한다.

## 5. 편집·실행 상태

1. 첫 진입: Kit 버전 또는 빈 기본 코드를 불러온다. 기존 초안이 있으면 마지막 수정 시각과 함께 `이어서 하기`를 기본으로 제시하고 `새로 시작`은 별도 선택으로 둔다.
2. 입력: 사용자가 타이핑을 멈춘 뒤 약 800ms 후 자동 실행한다. 자동 실행은 기본 켜짐이며 사용자가 끌 수 있다. `Run`은 즉시 실행한다.
3. 저장: 실행 직전 최신 코드를 브라우저 저장소에 기록한다. 별도로 짧은 입력 지연 후에도 초안을 저장하고, 페이지 이탈·새로고침 시 복원한다. 저장이 실패하면 자동 실행을 멈추고 명시적인 오류와 코드 복사·내보내기 경로를 제공한다. 사용자가 코드를 확보한 뒤 `저장 없이 한 번 실행`을 명시적으로 선택할 수 있지만, 저장 성공으로 표시하지 않는다.
4. 실행: 매번 새 격리 Preview를 만들고 이전 실행을 제거한다. 늦게 도착한 이전 실행의 로그·결과는 현재 화면에 반영하지 않는다. `다시 실행`은 현재 저장된 코드를 사용한다.
5. 성공: 로드·heartbeat·필수 리소스·처리되지 않은 오류를 확인한 뒤 해당 코드를 `마지막 정상 코드`로 보관한다. 애니메이션의 미적 완성도까지 자동 판정했다는 의미는 아니다.
6. 실패: 코드 오류는 편집을 막지 않고 Console에 표시한다. 응답 없음이나 환경 중단이 연속 3회 발생하면 자동 실행을 끄고 이유, `Run`, `마지막 정상 코드 복구`를 보여준다. 단순 문법 오류 3회만으로 자동 실행을 끄지 않는다.
7. 복구: `마지막 정상 코드`는 현재 초안을 덮어쓰므로 변경 내용이 있을 때 확인 단계를 둔다. `초기화`는 원래 Kit 또는 빈 기본 코드로 돌아가며 현재 초안은 복구 가능 스냅샷으로 먼저 보관한다.

Preview 상태는 `준비 중 → 실행 중 → 정상/코드 오류/환경 오류/시간 초과`로 표현한다. 실행 중 상태가 오래 남지 않도록 제한 시간을 둔다. 사용자가 Preview 탭을 떠나거나 페이지를 닫으면 실행 iframe을 제거한다.

## 6. 브라우저 저장과 CodePen 내보내기

- IndexedDB에는 초안 ID, 연관 예제 ID, Kit 버전, 세 코드 파일, 수정 시각, 마지막 정상 코드와 저장 형식을 둔다. 최근 연습 목록에는 제목·참고 예제·수정 시각만 사용한다. 개인 코드와 Console 내용은 D1·Analytics·오류 로그로 전송하지 않는다.
- 같은 예제에서 다시 들어오면 기존 초안을 이어갈지 새 초안을 만들지 선택할 수 있다. Kit이 갱신돼도 기존 초안을 자동으로 덮어쓰지 않으며, 새 버전으로 시작하기를 별도 제공한다.
- 브라우저 데이터 삭제 또는 기기 변경 시 초안이 사라질 수 있음을 최초 저장 때 짧게 안내한다. 저장량·초안 수의 제한과 실패 상태를 UI에서 설명한다.
- `CodePen으로 보내기`는 **현재 편집 중인 세 파일**을 사용자의 명시적 클릭으로 CodePen prefill에 전달한다. 출처·라이선스 고지가 필요한 Kit은 함께 포함한다. 전송 전에 외부 서비스로 코드가 넘어간다는 사실을 버튼 주변에 표시한다. 팝업 차단 또는 전송 실패 시 현재 초안을 보존하고 복사 가능한 코드와 재시도를 제공한다. 구현은 [CodePen의 POST prefill 문서](https://blog.codepen.io/docs/api/post-to-prefill-pen/)를 따른다.

## 7. 실행 격리와 안전 기준

- 사용자가 편집한 코드는 앱·관리자·API와 다른 Preview 출처에서 `sandbox` iframe으로 실행한다. 코드는 브라우저 안에서 Preview에 전달하고 실행을 위해 서버에 업로드하지 않는다. 내부 CodePackage에 외부 CodePen용 `allow-same-origin allow-forms allow-popups` 구성을 재사용하지 않는다.
- iframe에는 실행에 필요한 스크립트 권한만 주고 동일 출처, 상위 페이지 이동, 팝업, 다운로드, 폼 제출, 카메라·마이크·위치 권한을 주지 않는다. 인증 쿠키, API 키, 저장된 초안 전체를 전달하지 않는다.
- 실행에 필요한 GSAP 등 라이브러리와 에셋은 허용 목록·고정 버전으로 제공한다. 빈 기본 코드는 외부 라이브러리 없이 시작하고, GSAP 예제 참고 시에는 허용된 GSAP 추가 선택지를 안내한다. 임의 외부 URL은 초기 버전에서 실행하지 않는다.
- 부모와 Preview 사이에는 현재 실행 ID에 묶인 메시지 채널로 상태·제한된 Console 메시지만 교환한다. 알 수 없는 메시지와 이전 실행 메시지는 폐기한다.
- heartbeat·시간 초과·로그 수·출력 크기 제한을 둔다. 브라우저에서 모든 무한 루프를 미리 검출할 수 있다고 주장하지 않는다. 응답이 없으면 iframe을 제거하고 새 실행으로 복구한다.
- 구체적인 Preview 출처, CSP, 허용 리소스와 메시지 계약은 구현 전에 기술 설계와 자동 검사를 확정한다.

## 8. 접근성·측정·완료 기준

- 탭, Run, 자동 실행, Console과 조절 손잡이는 키보드로 조작할 수 있다. 조절 손잡이에는 키보드 단위 조정과 현재 비율을 제공한다.
- 저장·실행·오류 상태는 색상 외에 텍스트와 아이콘으로 알린다. 상태 변경은 필요한 경우에만 보조 기술에 알리고 타이핑마다 반복해서 읽지 않는다.
- `prefers-reduced-motion`에서는 작업 공간 UI 전환 효과를 줄인다. 사용자가 작성한 Preview 자체의 모션은 Preview 안에서 제어한다.
- 익명 집계는 연습 시작, Run, 저장 실패, CodePen 내보내기 성공 여부만 센다. 코드·Console·초안 ID·원본 URL의 불필요한 세부값은 전송하지 않는다.

Phase 2 완료는 `PHASE2_EXECUTION_PLAN.md`의 수용 기준으로 판정한다. 최소 10개의 Practice Ready Kit은 권리·실행·복구·내보내기 검증을 각각 통과해야 한다. 모든 공개 원본 Pen은 Kit 여부와 무관하게 빈 코드 연습에 들어갈 수 있어야 한다. 미션과 자동 판정은 Phase 3 출시 전까지 화면에서 숨긴다.
