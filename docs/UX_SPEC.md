# 사용자 경험 상세 명세

문서 상태: Draft v0.2
범위: Phase 1 사용자 화면과 Phase 2 연습 화면의 기준

관리자 화면의 상세 흐름은 `ADMIN_REVIEW_SPEC.md`를 따른다.
Phase 1 공개 화면의 실제 구성은 `PUBLIC_SCREEN_SPEC.md`, 공통 시각 기준은 `DESIGN_SYSTEM.md`를 따른다.

## 1. 경험 목표

사용자는 로그인이나 사용법 학습 없이 다음 일을 할 수 있어야 한다.

1. 원하는 애니메이션을 검색하거나 둘러본다.
2. 결과를 실제 코드 실행 화면으로 확인한다.
3. 기술, 트리거, 움직임과 적용 영역을 이해한다.
4. 비슷한 예제로 이동한다.
5. 마음에 드는 예제를 저장하거나 연습을 시작한다.

## 2. 전역 내비게이션

```text
Phase 1: Kwak Motion Lab | Explore | Sections | About | Saved | Theme
Phase 2: + Practice
Phase 3: + Learn
```

- 로고를 누르면 Home으로 이동한다.
- 현재 메뉴를 시각적으로 구분한다.
- 모바일에서는 메뉴를 열고 닫을 수 있다.
- 검색은 Home과 Explore에서 가장 강하게 제공하고, 데스크톱 헤더에서는 빠른 검색 진입을 제공한다.
- 로그인 버튼은 제공하지 않는다.

## 3. Home

### 목적

사이트의 성격을 전달하고 검색, 대표 컬렉션과 Section 탐색으로 빠르게 연결한다.

### 섹션 순서

1. Header
2. Interactive Hero
3. 자연어 검색
4. 추천 컬렉션
5. 최근 추가 콘텐츠
6. Section 탐색
7. 인기 패턴
8. URL 제보
9. Footer

연습 가능한 콘텐츠는 Phase 2, 학습 시작은 Phase 3에 실제 콘텐츠가 준비된 뒤 추가한다.

### Interactive Hero

- 왼쪽에는 브랜드 메시지와 주요 행동을 둔다.
- 오른쪽 또는 배경에는 실제 코드로 실행되는 대표 예제를 둔다.
- Phase 1 주요 행동은 `애니메이션 둘러보기`와 `URL 제보하기`다. Phase 2부터 두 번째 행동을 `연습 시작하기`로 교체하거나 함께 제공한다.
- 대표 예제가 실패해도 Hero의 텍스트와 탐색 기능은 정상 동작해야 한다.
- 움직임 감소 환경에서는 장식 모션을 줄이되 사용자가 Run을 눌러 예제를 실행할 수 있다.

### 검색

- 한국어와 영어 키워드를 허용한다.
- 자연어 예시를 placeholder 또는 추천 검색어로 보여주되 Phase 1에서는 일반 키워드 검색으로 처리한다.
- 검색 실행 후 Explore로 이동하며 검색어와 해석된 필터를 URL에 보존한다.

## 4. Explore

### 기본 구성

```text
페이지 제목 및 결과 수
검색 입력
필터와 적용된 조건
정렬 및 보기 방식
실행형 카드 목록
다음 결과 불러오기
```

### 필터

- Technology
- Trigger
- Motion
- Section
- Technique
- Difficulty
- Content Status

필터는 여러 축을 조합할 수 있다. 같은 축 안에서는 기본적으로 OR, 다른 축 사이에서는 AND로 처리한다.

예:

```text
(GSAP OR CSS) AND Scroll AND Hero
```

### 필터 상태

- 적용된 필터를 chip으로 표시한다.
- chip 하나를 제거할 수 있다.
- 전체 초기화를 제공한다.
- 뒤로가기를 사용하면 이전 검색과 스크롤 위치를 복원한다.
- 모바일 필터는 drawer로 제공하며 적용 결과 수를 버튼에 표시한다.

### 정렬

- 추천순
- 최신순
- 인기순
- 난이도순

추천순의 계산 근거는 내부 점수로 관리하되 사용자에게 모호한 정밀 점수를 노출하지 않는다.

## 5. 실행형 카드

### 표시 정보

- 실제 코드 Preview
- 제목
- 한 줄 설명
- 핵심 태그 2~4개
- 난이도
- Practice 또는 Tutorial 제공 상태는 해당 기능 출시 후 표시
- 저장 버튼

### 실행 정책

- 화면에 가까운 카드부터 Preview를 준비한다.
- 화면에 실제로 보이는 카드만 실행한다.
- 동시에 실행하는 카드 수를 제한한다.
- 무거운 예제는 `Run`을 누른 뒤 실행한다.
- 화면 밖으로 이동하면 일시정지하거나 Preview를 제거한다.
- Preview 오류는 카드 내부에서 처리하고 전체 목록을 중단시키지 않는다.

### 상호작용

- 카드 정보 영역을 누르면 상세로 이동한다.
- 카드 안에서 실행해야 하는 인터랙션과 상세 이동 동작이 충돌하지 않게 Preview와 정보 영역을 분리한다.
- 저장 버튼은 상세로 이동하지 않고 즉시 상태를 변경한다.
- 키보드로 Preview 실행, 카드 열기와 저장을 수행할 수 있어야 한다.

## 7. 콘텐츠 상세

### 정보 순서

1. 제목, 설명, 상태와 저장
2. 태그, 난이도와 제작 방식
3. 큰 실행 Preview
4. Preview 제어
5. Phase 1은 Overview와 Related, 이후 단계에서 Code와 Learn 추가
6. 주요 행동
7. 관련 Pattern과 예제

### Preview 제어

- 실행 또는 재시작
- 전체 화면
- 새 창
- 소리가 있는 경우에만 소리 제어
- 인터랙션 사용법

### 주요 행동

- `자유 연습`
- `단계별 학습`
- `CodePen에서 열기`
- `나중에 연습`

제공되지 않는 기능은 비활성 버튼으로 기대를 만들지 않고 숨기거나 `요청하기`로 명확하게 표현한다.

### 출처 표시

- 원본 CodePen은 제작자, Pen 제목과 원본 링크를 표시한다.
- 외부 코드를 사용한 경우 라이선스를 표시한다.
- 새 코드와 샘플 에셋으로 제작한 일반 패턴 예제는 Kwak Motion Lab 제작물로 표시한다.

## 8. 검색 결과 없음

단순히 빈 화면을 보여주지 않는다.

- 검색어 유지
- 적용된 필터 표시
- 가장 제한적인 필터 제거 제안
- 가까운 태그 추천
- URL 제보 진입
- 인기 콘텐츠로 이동

향후 자연어 필터 해석이 활성화되어 조건을 완화하면 어떤 조건을 제거했는지 표시한다.

## 9. 저장과 나중에 연습

- 로그인 없이 브라우저에 저장한다.
- `저장한 예제`와 `나중에 연습`을 구분한다.
- 저장 상태는 카드와 상세에서 동일하게 보인다.
- 브라우저 데이터 삭제 시 사라질 수 있다는 점을 최초 사용 시 간단히 안내한다.
- 데이터 내보내기는 초기 범위에서 제외한다.

## 10. URL 제보

### 입력

- URL
- 선택적인 한 줄 설명
- 선택적인 예상 태그

### 결과

- 정상 접수
- 이미 등록됨
- 이미 검토 중
- 지원하지 않는 URL
- 일시적인 확인 실패

제보는 공개로 바로 이어지지 않고 Candidate Inbox로 이동한다. 로그인 대신 요청 빈도 제한과 기본적인 자동 스팸 검사를 사용한다.

## 11. Practice

### 데스크톱

```text
상단: 제목 / 자동 실행 / Run / 초기화 / CodePen / 나가기
본문: Code Editor | Live Preview
하단: Mission / Hint / Console
```

- 편집기와 Preview 폭을 조절할 수 있다.
- HTML, CSS와 JavaScript 탭을 제공한다.
- 실행 전 현재 코드를 브라우저에 저장한다.
- 자동 실행은 기본으로 켜고 사용자가 끌 수 있다.
- 연속 실패하면 수동 실행으로 바뀐 이유를 알린다.

### 모바일

- Code, Preview와 Mission을 탭으로 전환한다.
- Preview 전체 화면을 제공한다.
- 작은 화면에서 코드와 Preview를 동시에 강제로 표시하지 않는다.

### 실패 상태

- 오류 요약과 위치
- 마지막 정상 상태로 복구
- 다시 실행
- 자동 실행 끄기
- 초기 상태로 복원

## 13. 테마

- 최초 기본값은 Light다.
- 사용자가 선택한 Dark 설정은 브라우저에 저장한다.
- 두 테마 모두 텍스트, 경계와 focus 상태의 대비를 확보한다.
- 실행 Preview의 자체 테마는 사이트 테마에 강제로 맞추지 않는다.

## 14. 반응형 기준

- Wide 1440px 이상: 카드 4열
- Desktop 1024~1439px: 카드 3열, sticky 필터
- Tablet 640~1023px: 카드 2열, 필터 drawer
- Mobile 639px 이하: 카드 1열, 필터 drawer

## 15. 접근성

- 모든 기능을 키보드로 사용할 수 있어야 한다.
- focus 표시를 제거하지 않는다.
- 장식 모션은 움직임 감소 설정을 존중한다.
- 실제 학습 대상인 Preview 모션은 설명과 수동 Run을 제공한다.
- 색상만으로 상태를 구분하지 않는다.
- iframe과 Preview에 구체적인 title을 제공한다.
- 오류 메시지는 해당 입력 또는 Preview와 연결한다.

## 16. 로딩과 오류

- 페이지 뼈대는 Preview보다 먼저 표시한다.
- Preview 로딩이 탐색과 텍스트 읽기를 막지 않는다.
- CodePen 오류와 내부 Preview 오류를 구분한다.
- 재시도 가능한 오류에는 명확한 재시도 행동을 제공한다.
- 공개 중지된 콘텐츠는 관련 추천에서 제거한다.

## 17. Phase 1 제외 범위

- 사용자 회원가입
- 사용자 지정 컬렉션
- 댓글과 커뮤니티
- 결제
- 클라우드 코드 저장
- 일반 웹 사례 자동 코드 생성
- 단계별 미션 실행

제외 기능의 진입점을 미리 노출해 빈 화면이나 준비 중 페이지를 만들지 않는다.

## 18. UX 검증 항목

- 처음 방문한 사용자가 설명 없이 실행 예제를 찾을 수 있는가
- 검색에서 실행까지 불필요한 로그인이나 모달이 없는가
- 카드 실행과 상세 이동이 충돌하지 않는가
- 많은 Preview가 브라우저 반응성을 떨어뜨리지 않는가
- 뒤로가기로 탐색 상태가 복원되는가
- 오류가 한 카드 또는 Preview 안에 격리되는가
- 모바일에서도 실행과 탐색의 핵심 흐름이 유지되는가
