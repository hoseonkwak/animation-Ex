# 애니메이션 탐색 범위 확대

상태: Spark 수집 구현 검증 · 운영 등록 확인 전  
확인일: 2026-11-05  
목적: WSSS의 오래된 GSAP 목록만 매일 확인하는 상태에서, 새로 올라오는 실행 가능한 예제와 재구성할 웹 사례를 폭넓게 찾는 체계로 바꾼다.

현재 운영 예약은 아직 WSSS GSAP 매일 수집이다. 이 문서의 출처·주기는 구현과 검증을 거쳐 배포할 때 적용한다.

## 1. 현재 문제

- 예약 작업은 매일 WSSS `Animation/GSAP` 첫 페이지만 확인한다. 이 카테고리는 15개 글의 checkpoint가 이미 완료됐고, 목록의 가장 최근 글은 2021-04-21에 게시됐다.
- WSSS 홈에서 가장 최근에 보이는 글도 2024-08-09 게시물이다. 매일 0건은 파서 실패의 증거가 아니지만, 현재 출처만으로 새 예제를 계속 확보할 수 없다는 증거다.
- 관리자 화면의 신규 후보 수만으로는 실제로 어디를 몇 건 확인했는지 알 수 없다.

## 2. 탐색 대상

| 경로            | 찾을 것                                           | 공개 전 조건                                                               |
| --------------- | ------------------------------------------------- | -------------------------------------------------------------------------- |
| 실행 가능한 Pen | 공개 CodePen의 실제 Pen 링크와 제작자             | 현재 Embed가 실행되는지 확인. 원본 코드와 에셋은 복사하지 않음             |
| 튜토리얼·데모   | 애니메이션 글에 연결된 Pen 또는 독립 데모         | Pen이면 위 조건 적용. 그 외에는 자체 제작 코드가 준비될 때까지 재구성 대기 |
| 실제 웹 사례    | 애니메이션이 포함된 섹션, 특히 Hero·Scroll·Slider | 화면을 분석해 샘플 문구·이미지·SVG와 자체 코드로 재구성한 뒤 실행 검증     |

기술은 GSAP에 한정하지 않는다. CSS, SVG, Canvas, WebGL·Three.js와 브라우저 기본 API를 포함한다. 찾기 우선순위는 Hero, Scroll, Slider, 버튼·호버, 텍스트, 로딩·전환, 갤러리, 3D 순서다. 어려운 3D 사례도 발견 기록은 남기되 코드 제작과 검증이 끝나기 전에는 공개 예제로 세지 않는다.

## 3. 출처의 첫 구성

| 출처                                                      | 역할·주기                                               | 2026-11-05 확인 결과                                                | 도입 판단                                                                   |
| --------------------------------------------------------- | ------------------------------------------------------- | ------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| [CodePen Spark 공개 피드](https://codepen.io/spark/feed/) | 새 Pen 발견, 매일 확인                                  | HTTP 200, 최근 호 10개, 첫 호의 고유 Pen 링크 9개                   | 첫 자동 수집 대상으로 채택. 주간 발행이라 매일 신규를 보장하지는 않음       |
| [CSS-Tricks RSS](https://css-tricks.com/feed/)            | 애니메이션·CSS 글의 Pen 링크 발견, 매일 확인            | HTTP 200, 최근 글 15개. 표본 3개에는 Pen 링크 없음                  | 글 유형·태그 선별과 실제 링크 수율을 측정하는 파일럿                        |
| [DEV/Forem 공개 API](https://developers.forem.com/api/v1) | `gsap`, `animation`, `css` 등의 최근 글 발견, 매일 확인 | 공개 태그 조회 성공. 최근 글 표본 3개에는 Pen 링크 없음             | 잡음이 많으므로 본문에서 직접 Pen 링크가 확인된 항목만 후보화하는 파일럿    |
| [WSSS](https://wsss.tistory.com/)                         | 이미 수집한 보관 예제의 변경 감시, 주 1회               | GSAP 최신 글 2021년, 사이트 홈 최신 글 2024년                       | 신규 확보의 주력에서 제외. 카테고리 전체를 매일 재요청하지 않음             |
| [Codrops Creative Hub](https://tympanus.net/codrops/hub/) | 새 데모와 실제 웹 사례의 발견, 접근성 확인 후           | 공개 페이지에는 2026년 신규 데모가 있으나 현재 수집 요청은 HTTP 403 | 우회 수집하지 않음. 접근 가능한 공식 경로가 확인되기 전에는 자동화하지 않음 |

CodePen의 과거 Picks·Popular·Recent 및 Collection 피드는 이번 확인에서 HTTP 403이었다. 현재 접근 가능한 출처로 가정하지 않는다. [CodePen API v2](https://blog.codepen.io/docs/api/api-v2/)는 계정 소유 Pen 중심이므로 다른 제작자의 공개 Pen을 폭넓게 찾는 API로 쓰지 않는다.

출처를 늘릴 때는 공개 피드나 공식 API를 우선하고 robots·이용 조건·응답 코드를 출처별로 검증한다. 403 또는 429는 우회하지 않고 해당 출처의 실패 상태를 기록한다. 사이트별 요청은 직렬·제한된 속도로 실행하며 파일, 이미지와 원본 코드를 내려받지 않는다.

## 4. 공통 발견 흐름

```text
출처 목록/피드 확인
→ 원문 URL과 발견 경로 기록
→ Pen·데모·웹 사례 유형 판별
→ canonical URL 기준 중복 제거
→ 실행 가능 여부에 따라 후보/재구성 대기로 분기
→ 기존 품질 게이트
→ 공개
```

- 같은 Pen이 Spark, 기사, WSSS에 모두 등장하면 후보는 하나로 유지하고 발견 경로를 모두 남긴다.
- 코드로 실행할 수 있는 자료가 없는 외부 데모를 동영상이나 GIF만으로 공개하지 않는다.
- 새로운 출처는 GSAP·Loading에 한정된 기존 자동 공개 정책을 확대하지 않는다. 출처별 표본과 실행 검증이 쌓인 뒤 별도로 결정한다.
- CodePen Spark의 최신 링크는 `codepen.io/editor/{creator}/pen/{UUID}` 형식도 사용한다. 현재 정규화기는 구형 영숫자 Pen ID만 허용하므로 **2.0 URL 정규화와 Embed 실행 검증이 첫 수집 구현의 선행 조건**이다.

## 5. 수집 결과 보고

매 실행 및 출처별로 `확인한 목록 수 → 발견 링크 수 → 신규 고유 URL 수 → 중복 수 → 후보 등록 수 → 실행 검증 수 → 공개 수`를 구분한다. 신규 후보가 0건이면 `새 글 없음`, `모두 중복`, `Pen 링크 없음`, `접근 차단`, `파서 실패` 중 실제 원인을 기록한다. 출처 이름, 마지막 성공 시각, 마지막 새 후보 시각과 다음 확인 시각을 관리자에게 보여준다. 신규 후보와 공개 예제 수를 섞어 보고하지 않는다.

## 6. 적용 순서와 완료 조건

1. Spark RSS 파서, 구형·2.0 Pen URL 정규화와 실제 Embed 실행 검증을 만든다. 피드의 광고·외부 기사 링크는 후보로 넣지 않는다.
2. 출처별 실행·발견 건수와 0건 사유를 저장하고 관리자 보고에 연결한다.
3. CSS-Tricks와 Forem의 소규모 읽기 전용 파일럿으로 Pen 링크 수율과 잡음을 측정한 뒤 운영 자동 수집 여부를 정한다.
4. WSSS 주간 감시와 웹 사례 재구성 대기를 분리한다. Codrops 등 403 출처는 접근 가능한 공식 경로가 확인될 때만 추가한다.

첫 운영 완료 조건은 Spark에서 실제 새 Pen을 발견해 중복 없이 후보에 기록하고, 소유자가 관리자 화면에서 출처·건수·실행 근거를 확인하는 것이다. 새 Pen이 없는 날에도 모든 활성 출처의 성공 또는 실패 원인을 설명할 수 있어야 한다. 공개 예제 증가는 별도 실행 품질 게이트를 통과한 뒤에만 완료로 본다.

## 7. 읽기 전용 발견 파일럿 (2026-11-05)

- Spark 공개 RSS의 최근 10호에서 고유 Pen 링크 98개를 추출했다. 최신 호는 9개다.
- 운영 D1 `sources.canonical_url`과 구형·2.0 URL을 정규화해 대조한 결과 기존 항목 0개, 새 링크 98개였다. 이 가운데 2.0 주소가 92개, 구형 주소가 6개다.
- CSS-Tricks RSS의 최근 글 15개에는 직접 Pen 링크가 0개였다. 글 본문 추가 탐색은 이번 파일럿에서 하지 않았다.
- 98개 중 Spark 본문에서 제목과 설명을 붙여 주 예제로 소개한 Pen은 55개였다. 나머지 43개는 챌린지 참가작, 이전 작품 등 본문 안의 참고 링크다. 98개를 모두 애니메이션 후보로 등록하면 주제와 품질이 섞인다.
- 55개를 인앱 브라우저에서 직접 열어 공개 상태, 빌드 결과와 실제 Preview iframe을 확인했다. **53개는 페이지와 실행 미리보기가 열렸고**, [`The Road Dreams`](https://codepen.io/editor/zhenyu-xiao/pen/019f90a0-d102-7736-8c0f-760b0bf76c7b)는 재확인해도 CodePen 404였다. [`Randomness (CSS Only)`](https://codepen.io/villepreux/pen/azdgZRG)는 구형 Pen에서 Preview가 열렸지만 정적인 CSS 난수 배치 예제다. 따라서 55개 중 54개가 열리고, 그중 신형 Pen 53개의 빌드 성공과 Preview를 확인했다.
- 설명과 제목으로 주제가 명확한 모션 예제는 39개다. 나머지 열리는 Pen 15개에는 정적 디자인·기능 데모나 모션 여부가 애매한 사례가 있어 개별 동작 검수가 필요하다. **39개는 모션 후보의 1차 선별 수**이며, 실제 동작·외부 자산·권리·우리 사이트의 Embed 정책을 모두 통과한 공개 가능 수가 아니다.
- 신형 주소의 실제 Embed [`Scroll-Driven Photo Gallery`](https://codepen.io/editor/cbolson/embed/01a187ae-e212-756d-8f6c-a76c594987bf)에서 Preview iframe이 `codepen.dev` 실행 화면과 이미지 요소를 렌더링하는 것을 확인했다. 편집기 화면의 빌드 성공만으로 Embed 동작을 가정하지 않았다. 개별 Pen의 화면 변화와 콘솔 오류는 전체 53개를 별도로 검사해야 한다.
- 이번 검사는 RSS, 운영 D1과 CodePen 공개 화면을 읽기만 했다. 후보 등록이나 공개는 하지 않았다. 명령줄의 CodePen 개별 페이지 요청은 HTTP 403이었지만, 브라우저 검사는 가능했다. 이 403을 Pen 자체의 실패로 분류하지 않는다.

## 8. Spark 수집 구현 진행 (2026-11-05)

- 공개 RSS의 `h3`에 소개 제목이 붙은 Pen만 추출하고, 제목·소개 문구에 모션 신호가 있는 항목만 후보로 만든다. 스폰서, 외부 기사, 정적 예제와 같은 Pen의 반복 링크는 제외한다. 이 선별은 공개 승인 근거가 아니다.
- CodePen 2.0의 `/editor/{creator}/pen/{uuid}`와 Embed URL을 별도로 정규화한다. 원본 코드·이미지·개별 Pen 페이지는 수집기가 내려받지 않는다.
- fixture와 API 계약 검사를 통과한 뒤 실행한 읽기 전용 preflight에서 최근 10호, 모션 후보 38건을 확인했다. 이는 기존 운영 D1과 대조하거나 실행 화면을 검증한 뒤의 최종 신규 건수가 아니다.
- 별도 `CodePen Spark ingestion` 예약 workflow는 09:53 KST에 실행한다. HMAC API는 Spark 발견 경로와 실행 checkpoint를 WSSS와 분리해 저장하며 관리자 수집 결과에 출처를 표시한다. 실제 운영 후보 등록과 다음 날 0건 사유 확인을 완료 증거로 남긴다.
